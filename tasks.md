## Medium Priority

- [x] CSRF review — reviewed 2026-08-09, no code changes needed (came back clean): traced the full auth flow end to end. The NestJS API (`ClerkAuthGuard`) accepts credentials only via an explicit `Authorization: Bearer <token>` header — never a cookie (`grep` for `cookie-parser`/`res.cookie`/`Set-Cookie` across `apps/api/src` found nothing) — so browsers never auto-attach it cross-site, which is what classic CSRF depends on. All 8 mutating `actions.ts` files under `apps/web/app` are genuine `"use server"` Server Actions (verified every one starts with the directive), which run through Next.js's framework-level CSRF check (`Origin` compared against `Host`/`X-Forwarded-Host`, mismatches rejected — confirmed current per https://nextjs.org/docs/app/guides/server-actions#security) — `next.config.mjs` has no `serverActions.allowedOrigins` override weakening it. The one client-side hook that calls the API directly with a bearer token (`use-proposals.ts`) is a read-only GET, not a mutation. The public marketing `POST /api/v1/marketing/subscribe` endpoint needs no ambient credential to reach (by design — anyone can already call it directly), so CSRF doesn't add anything beyond what's already true of a public endpoint. Also swept every `@Get()` across all API controllers — all read-only, no mutate-via-GET footgun.
- [x] Dependabot version updates configured (2026-08-08, `.github/dependabot.yml`): the clean `pnpm audit` from the devDependency-CVE fix was a point-in-time snapshot with no ongoing scanning behind it — new CVEs disclosed after today would go unnoticed. Two ecosystems: `npm` (covers this pnpm workspace natively — Dependabot detects `pnpm-lock.yaml` and the workspace from a single root `directory: "/"` entry, no per-package entries needed) and `github-actions` for the workflow files. Weekly on Mondays; minor/patch bumps grouped into one PR each run to avoid per-dependency noise, major bumps left ungrouped so they get the same one-at-a-time review this repo already gives major upgrades (e.g. the Next.js 14→16 migration). This only covers scheduled *version* updates — GitHub's separate "Dependabot alerts" / "Dependabot security updates" toggles (repo Settings → Code security and analysis) are account-admin settings not reachable from here; worth confirming they're on.
